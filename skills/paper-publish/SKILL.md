# paper-publish：发表与发布

## 目标

把论文生产技能（或用户直接提供的）成稿，安全、合规地发布到指定平台。核心原则：**格式与流程自动化，真实提交由用户完成或经用户明确授权**。

## 执行流程

覆盖投稿/发布全链路：**平台匹配 → 投稿准备 → 合规 → 提交 → 返修 → 发表 → 传播**。

### 阶段 1：目标平台匹配

- **前置要求**：目标平台/期刊应在论文写作阶段（paper-writing 阶段 0）已锁定，本阶段只做确认与复核，不做临时换刊——避免"定稿后才发现期刊不匹配整篇重写"。若成稿确实未定期刊，须回到 paper-writing 的 `../paper-writing/references/workflow.md` 步骤 0 重新评估。
- 用户指定平台；未指定时按体裁推荐（学术→期刊/arXiv，科普→公众号/知乎，技术→博客）。
- **工具辅助**：内置库匹配用 `journal_matcher(topic=..., paper_type=...)`；任意学科实时搜刊用 `journal_search_openalex(query=...)`（返回发文量/被引/h 指数/OA 状态）——两者结果都只是候选线索，最终以期刊官网《作者指南》为准。
- 依据 `references/journal-matching.md` 做五维评估（主题契合/层次/读者群/周期成本/录用可行性），锁定 TOP3 候选，并以最优先平台的《作者指南》为格式基准。
- 记录关键约束：字数、格式、是否原创首发、是否收费（APC）、审稿周期、预印本政策。

### 阶段 2：格式适配

依据 `references/publish-platforms.md` 的平台规则转换成稿：
- 学术期刊：生成投稿模板（标题、作者信息、摘要、关键词、正文、参考文献、伦理声明），转 PDF/LaTeX；
- 公众号：拆小节、配小标题、加导语与摘要框、控制段落长度（手机阅读）、标注图片来源；
- 知乎/博客：整理目录、加引用链接、保留可读的 Markdown。
- 转换后做一致性校验：正文无丢失、引用无错乱、公式/代码块完整。
- **PDF 投稿件**：转换完成后调用 `audit_pdf(pdf_path=...)` 做尽力级审计（文风/重复/对冲/数字与统计子集；中文 PDF 提取可能不完整，报告会如实标注跳过项）。

### 阶段 3：元信息与摘要

- 生成平台要求的元信息：标题、摘要（学术按期刊要求）、关键词 3-5 个。
- **机检把关**：`check_title(markdown=成稿)` 查标题长度带与空泛措辞；`check_abstract(markdown=成稿)` 查结构化四要素与篇幅——审稿人第一眼就是这两处，不达标先回写。
- 学术场景额外生成：通讯作者信息占位、利益冲突声明、基金项目（如用户提供）。

### 阶段 4：投稿信与投稿准备（学术投稿必做）

- 依据 `references/cover-letter.md` 生成 Cover Letter（5 段式：称呼 → 一句话核心贡献 → 与期刊契合 → 声明 → 结尾）。
- **投稿前强制门禁**：`verify_references(markdown=全文)` 批量核验参考文献——存在 C 级未确认条目即中止投稿准备，补来源后重跑；`proofread(markdown=全文)` ERROR 项清零。
- 逐项核对《投稿前材料核对清单》：格式合规、标题页、摘要、关键词、图表文件、补充材料、作者贡献声明、伦理审批、数据可用性声明、Cover Letter、参考文献完整、**参考文献 DOI 已按三重核对协议核验（见 paper-writing `../paper-writing/references/citation-guide.md`）**、查重/AI 披露。

### 阶段 5：伦理与合规检查

- 依据 `references/ethics-compliance.md` 逐项确认：
  - 作者署名满足 ICMJE 四标准；
  - 利益冲突已声明（无冲突也要写"声明无冲突"）；
  - 涉人/动物实验具备伦理审批号与知情同意；
  - 学术不端红线逐项自查：不伪造/不篡改/不抄袭/不幽灵引用/不一稿多投/不重复发表/AI 使用按期刊政策披露；
  - 查重提示：最终以目标期刊官方系统自检为准，本插件不做虚假承诺。
- 版权与原创：确认无未授权转载、无敏感信息；图/表来源标注。

### 阶段 6：提交执行

分两种模式，按用户授权执行：

1. **有平台 API / 已登录客户端可用时**：经用户明确授权后，调用对应工具提交；提交后回传确认结果。
2. **无 API / 需要人工登录时**：输出"投稿/发布操作指引"（目标 URL、账号登录点、填写字段、提交流程），并生成可直接复制的成稿文件，由用户完成最后一步。
3. 学术投稿同时给出预印本决策建议（arXiv/SSRN 等，先核对目标期刊预印本政策）。

### 阶段 7：审稿返修

- 收到审稿意见后，按 `references/revision-response.md` 执行：
  - 通读决定信与全部意见 → 逐条分类编号（实验类/写作类/文献类/质疑类/偏好类）；
  - 生成 Response Letter：每条意见"复述 → 致谢/判断 → 回应 + 修改位置"，逐条不漏；
  - 能改的改、有依据的合理拒绝并礼貌说明；修改稿标注改动处；
  - 区分"已修改 / 部分接受 / 不接受并说明理由"，绝不放空话。
- 修改稿定稿前重跑 `proofread` 与 `verify_references`（返修引入的新引用/新数据同样必须过门禁），报告随修改材料一并留档。
- 拒稿改投：按新目标期刊《作者指南》重新排版、重写 Cover Letter。

### 阶段 8：发表收尾

- 校样核对（数据/作者/单位/图表编号/参考文献，只改排版错误）。
- 开放获取决策（Gold/Green OA，核对基金开放要求）、版权确认。

### 阶段 9：发表后传播

- 依据 `references/post-publish.md` 制定传播计划：学术社交网络、预印本同步、个人主页、邮件列表、会议报告、科普渠道、媒体互动。
- 传播内容三要素：一句话版本 + 核心结果图 + DOI/代码/数据链接。
- 维护 Google Scholar Profile，追踪引用与 Altmetric；公开代码/数据须合规。

### 阶段 10：交付

- 交付：最终发布文件 + 元信息文本 + Cover Letter/Response Letter（如适用）+ （如适用）投稿回执/发布链接/传播物料。
- 明确区分状态：**已发布 / 待用户提交 / 修改中 / 草稿待定**，绝不把"已生成"写成"已发布"。

## 关键铁律

- 不伪造发布状态、回执号、链接。
- 不代替用户做涉及账号、支付、版权的决定。
- 学术投稿的最终查重、伦理审查、作者确认由用户负责。
- 返修 Response Letter 逐条回应且只陈述已真实完成的修改；传播内容忠于论文结论，禁止标题党夸大。
