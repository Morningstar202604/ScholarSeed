# top-conference-writing：顶会顶刊写作哲学（集成 ARS-ml-paper-writing）

面向 NeurIPS / ICML / ICLR / ACL / AAAI / COLM 及 Nature 系期刊的写作纪律。核心来源：ARS 的 ML 论文写作 skill（整合 Gopen & Swan、Ethan Perez、Zachary Lipton、Jacob Steinhardt 与 Neel Nanda 的实战经验）。

## 0. 最高铁律：绝不幻觉引用

AI 生成的参考文献**错误率约 40%**（论文不存在、作者错、年份错、DOI 伪造）。因此：

- **绝不凭记忆生成 BibTeX / 参考文献条目**；必须程序化获取（Crossref / Semantic Scholar / 客户端检索）。
- 无法程序化验证的引用：标记占位 `[待验证]` 并明确告知"以下 X 条引用我无法确认存在"。
- 引用规则见 `citation-guide.md` 与 `literature-search` 技能的 citation-audit。

## 1. 叙事三支柱（Introduction 结束前必须清晰）

1. **问题是什么**（读者能感知的痛点）；
2. **现有方法为何不够**（具体缺陷，非笼统"缺乏研究"）；
3. **我们的方案与凭据**（一句贡献 + 关键证据）。

**如果一句话说不清贡献，说明还没有一篇论文。** 动笔前先写出这句贡献句，写不出来就回去重想。

## 2. Gopen & Swan 句子级清晰七原则（节选）

| 原则 | 做法 |
|---|---|
| 主语紧跟论元 | 一句话的主语应是该句真正的主角，别把动词埋进从句 |
| 旧信息在前 | 承接上文的已知信息放句首，新信息放句尾（信息流稳定） |
| 强调位置 | 句子重心放在句尾，段首句是结论句 |
| 动词具体 | 用有内容的动词，避免"is related to / has been shown to"式空壳 |
| 句长有节奏 | 关键论证句可长，但每段至少一句短句锚定读者 |
| 指代明确 | 代词必须能唯一回指，禁止悬空 this/that |
| 段首点题 | 每段第一句让读者知道这段在论证什么 |

## 3. 微观写作技巧（Ethan Perez）

- 具体数字代替形容词：写"2.3× 加速"，不写"显著加速"；
- 每个 claim 给出证据引用或实验支撑，不给就删；
- 先写最直白的版本，再打磨，不追求首稿华丽。

## 4. 用词纪律（Zachary Lipton）

- 精确优先于简短（Jacob Steinhardt）：宁肯长一点也要无歧义；
- 术语全文统一，定义后不改用；
- 避免空洞强调词（novel/significant/outstanding 不配证据不用）。

## 5. 审稿人实际读什么

| 部分 | 阅读比例 | 应对 |
|---|---|---|
| 摘要 | 100% | 必须完美：问题-方法-结果-意义四要素 |
| Intro | 高 | 前 3 句定生死，三支柱在此立起 |
| 图表 | 高 | 图要自明（标题即结论） |
| 方法 | 仅感兴趣时 | 别把亮点埋在方法里，别 bury the lede |
| 实验 | 高 | 证据链完整、基线公平、消融充分 |

**底线**：摘要和 Intro 没钩住审稿人，再好的方法也没人读到。

## 6. 时间分配（Neel Nanda 实战）

写作比调参更花时间：初稿只追求"写完"，把 50%+ 时间留给重写与打磨；"写得快"靠的是每天稳定产出而非灵感。

## 7. 会议格式要求速查

- NeurIPS/ICML/ICLR：正文页数上限 9 页（+0），参考文献不计页数，须提交 paper checklist；
- 模板纪律：**复制整个模板目录再写**，禁止改动 .sty 风格文件，提交前对照官方 checklist。

## 8. 写作流程（迭代而非线性）

每步 = 起草 → 反馈 → 修订，禁止一步到位：

1. 定贡献句（三支柱）→ 2. 定结构（Storyboard）→ 3. 写 Intro/摘要 → 4. 实验补证据 → 5. 方法/相关工作 → 6. 全文一致性 → 7. 论文 checklist → 8. 反复打磨。
