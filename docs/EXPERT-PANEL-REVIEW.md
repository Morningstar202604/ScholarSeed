## 二、执行摘要（全体表决）

**总评：B+（有真实差异化价值的产品，工程纪律优秀，但分发、校准闭环和商业模式三块短板限制其市场竞争力。）**

| 维度 | 评分（10 分制） | 一句话判词 |
|---|---|---|
| 技术差异化 | **9** | 确定性规则 + 可复现证据 + 零依赖，业内几乎无同类 |
| 工程纪律 | 8.5 | 174 测试全绿、CI 3.9–3.13、release gate、诚实标注局限 |
| 架构可维护性 | 6 | 单文件 162KB 单体是最大技术债 |
| 校准完备度 | 6.5 | 只有"人类论文零误报"，没有 AI 阳性检出率；人文未校准 |
| 分发与获客 | 4 | "把文件夹拖进插件目录"挡住 95% 的潜在用户 |
| 商业模式 | 3 | Apache 2.0 全免费，无任何变现路径设计 |
| 合规与信任资产 | 7 | hints-not-verdicts 立场正确；隐私披露不足 |

**三个最致命的问题（按优先级）：**
1. **分发摩擦**：没有 pip 包、没有一键安装、没有网页 demo——好产品到不了用户手里。
2. **信任缺口**：核心卖点之一是 AI 痕迹画像，但公开材料承认"未建立 AI 代写正样本对照"。竞品会拿这一点攻击你。
3. **单体文件**：`paper_tools.py` 162KB 单文件让外部贡献者望而却步，社区飞轮转不起来。

## 三、各委员会意见

### 3.1 产品委员会（8 人）

**肯定**
- "审计而非代写"的定位在道德高地上，且与全球期刊 AI 披露政策（COPE、各大出版商）同频，是政策红利期。
- 用户旅程完整：选题→检索→大纲→写作→引文→格式→自审，32 个工具覆盖全流程，`audit_paper` 一键体检是好入口。
- `audit_project` 多章学位论文审计切中中国硕博刚需，这是中文市场的钩子功能。

**问题**
- 无用户画像分层文档：研究生、导师、期刊编辑、科研诚信办四类用户的入口工具完全不同，但 README 只有一张工具大表。
- 免费工具太多且平铺——32 个工具没有一个"付费墙后"的价值梯度，也没有引导路径（哪个先试？哪个惊艳？）。

**建议**
- 定义 4 类 Persona 各一条 5 分钟 Quick Path 写进 README。
- 把 `verify_references` 和 `audit_paper` 立为旗舰入口，其余工具作为深度能力被引用。

### 3.2 工程架构委员会（10 人）

**肯定**
- 纯 stdlib 零依赖是杀手级部署优势：任何有 Python 的机器直接跑，CI 里不用装环境。
- `cli.py` 与 MCP server 同引擎双出口，人机两用，设计正确。
- 缓存 TTL 可调、API 礼貌重试、`--fail-on` 退出码约定，都是生产级细节。

**问题**
- `paper_tools.py` 约 162KB 单文件承载全部 32 工具：无法按需导入、diff 噪声大、code review 困难、新人贡献门槛极高。
- 无 `pyproject.toml`，不能 `pip install scholarseed`，不能作为库被其他项目 import。
- 性能基线缺失：长文档（10 万字+学位论文合并审计）无耗时/内存数据。

**建议**
- **拆包为标准 Python 包结构**（保持零依赖硬约束不变）：`scholarseed/checkers/*`、`scholarseed/sources/*`（Crossref/S2/OpenAlex 适配器隔离）、`scholarseed/report/*`；MCP server 与 CLI 变成薄入口。
- 加 `pyproject.toml`，发 PyPI；可选重组件（PDF/docx 解析）放 `[extras]`，核心保持纯 stdlib。

### 3.3 质量与测试委员会（6 人）

**肯定**
- 174 用例含植入缺陷回归（129+），配合"每次阈值调整必须重跑全量"的军规，是同类开源项目罕见的纪律。

**问题**
- 只有 2 个测试文件，单测与实现同文件巨石耦合；无 property-based 测试（切句/词统计这类逻辑非常适合）；无模糊测试。
- 外部 API 调用（Crossref/S2/OpenAlex）无契约测试或录放（record/replay）夹具，网络抖动会让 CI 不稳定，重构 sources 层时无保护网。

**建议**
- 拆包时同步按模块拆测试；为 HTTP 层加录制回放夹具；引入 hypothesis 做属性测试（dev 依赖，不影响运行时零依赖承诺）。

### 3.4 学术诚信研究委员会（7 人）

**肯定**
- A/B/C 分级、DOI 优先匹配、标题相似度阈值防误配、"no entry unless verified" 的反幻觉门禁——方法论严谨。
- 明确拒绝做"AI 代写判决器"、所有启发式输出标注为提示——这是本项目最重要的免责立场，务必坚持。

**问题**
- 学科覆盖不均：70 篇校准语料全部 STEM，人文阐释文体明确未校准；法学、医学案例报告、社科质性研究的文本形态差异极大。
- 中文文献生态缺位：知网/CNKI 无 API 对接，GB/T 7714 有格式生成但中文引文核验只能走 Crossref（收录有限）——中文市场核心痛点没解决透。

**建议**
- 公开征集人文/社科语料志愿者，分阶段扩校准矩阵；短期内在 humanities 模式输出中显式标注"未经定量校准"（已有，保持）。
- 中文核验路线：优先对接 OpenAlex 中文期刊覆盖 + DOI 中文前缀（如 ISTIC），并诚实标注覆盖率；不做爬虫侵权方案。

### 3.5 数据与 AI 研究委员会（6 人）

**肯定**
- CORPUS-BENCHMARK 的方法论（分布级调参、防过拟合军规、聚合统计不含原文）经得起审视，可作为信任资产对外传播。

**问题（全场最尖锐的一条意见）**
- **只有负样本对照（70/70 低分=零误报），没有正样本召回率**。"AI 痕迹画像"这一卖点目前无法回答"它能查出多少 AI 写的东西"。竞品与审稿人一定会问。
- econ.GN 两篇拉低均值暴露了分数对"未打磨"与"AI 生成"两类低分的混淆——需要第二轴区分"粗糙"与"可疑"。

**建议（高优先级）**
- 构建 **AI 阳性对照集**：用主流 LLM 在受控提示下生成 50–100 篇各体裁文本（含"诱导规避检测"的对抗子集），公开检出率/召回率/ROC。哪怕数字不好看，诚实的测量本身就是竞争力——市面上多数竞品根本不敢公开这个数字。
- 报告分数拆为两个独立维度：`polish（打磨度）` 与 `ai-likeness（AI 相似度）`，消除语义混淆。

### 3.6 市场与增长委员会（9 人）

**竞争格局**

| 竞品 | 类型 | 强项 | 弱项（你的机会） |
|---|---|---|---|
| Turnitin / iThenticate | 机构查重 | 机构垄断、数据库大 | 贵、面向机构不面向作者、无引文真实性核验、闭源黑箱 |
| Paperpal / Writefull | AI 润色 SaaS | 体验好、有期刊合作 | LLM 生成式=自身即幻觉源；订阅制贵 |
| Jenni AI / SciSpace | AI 写作助手 | 增长快 | 是"问题的一部分"而非解决方案 |
| GitHub 散装 lint 脚本 | 开源工具 | 免费 | 无核验 API、无基准、无维护 |

**定位建议：不做第 N 个 AI 写作助手，做"学术论文的 Ruff + CI 门禁"。**
- 确定性、可复现、可解释、可进 CI——这四个属性上面所有竞品都不具备，是唯一空位。
- 口号方向："Every citation auditable. Every check reproducible."（已有雏形，强化传播）
- 渠道打法：① 高校研究生社群（知乎/B站/小红书的论文季内容营销）；② 开源实验室 LaTeX 仓库的 CI 门禁模板（病毒式传播点）；③ 期刊编辑部预审试点（慢但壁垒深）。
- 北极星指标候选：每周被核验的引文数 > Star 数；CI 门禁周运行次数 > 下载量。

### 3.7 开发者生态与分发委员会（7 人）

**肯定**
- 已有 Smithery 配置；Agent Plugins 1.0 规范卡位早；GitCode/Gitee/GitHub 三平台镜像意识好。

**问题**
- 最大问题仍是安装：README 第一步是"把这个文件夹拖进插件目录"。对比竞品 `pip install paperpal` 或网页直接用，流失率可想而知。
- 未提交 MCP 官方 Registry；无 VS Code 扩展（哪怕只是包一层 CLI）；无 GitHub Action（CI 门禁场景的最佳载体居然要用户自己写 workflow）。

**建议（按 ROI 排序）**
1. `pip install scholarseed` + PyPI 首页（解锁一切后续）
2. 官方 GitHub Action `scholarseed/gate-action`：两行 yaml 给任意论文仓加引文门禁——这是最强的增长杠杆
3. 提交 MCP Registry + Smithery 上架打磨
4. Web Playground（Pyodide 在浏览器跑核心检查器，零服务器成本 demo）
5. VS Code 扩展（Markdown/LaTeX 内保存即 proofread）

### 3.8 商业化委员会（6 人）

**现状**：Apache 2.0 全免费、无 CLA、无任何收入设计。委员会一致认为"现在谈收费太早，但现在就要设计梯度，否则永远只有免费"。

**Open-Core 三层模型建议**
| 层 | 内容 | 价格 |
|---|---|---|
| Community（永久开源） | 现有全部 CLI/MCP 能力 | 免费 |
| Team（SaaS） | 聚合报告仪表盘、课题组多人协作、历史趋势、批量学位论文审计 | ¥/月 订阅 |
| Institution（私有化） | 期刊预审工作流、院系级部署、SSO、审计日志 | 年度授权 |

- 前提：核心继续开源换增长与信任，增值在"聚合、持久化、协作、规模化"——这些恰是 CLI 天然给不了的。
- 融资/基金叙事：AI 内容泛滥→期刊强制 AI 披露→诚信审核工具成为基础设施；确定性工具是 LLM 工具的反面互补品。

### 3.9 安全与合规委员会（5 人）

**肯定**：SECURITY.md 存在、无捆绑凭据、缓存可控、AIGC 披露符合国内平台规范（罕见加分项）。

**问题**
- **隐私未充分披露**：`citation_verify` 会把稿件中的标题明文发送给 Crossref/Semantic Scholar——未发表稿件标题属于敏感内容，需在 README 显著位置披露并提供 `--offline`/白名单选项。
- 依赖外部 API 的可用性与条款变更风险（S2 曾限流收紧）；单一供应商故障会击穿核心功能。
- "AI 痕迹分数"若被第三方滥用作处分依据存在声誉/法律外溢风险——文档中"不得用于处罚决定"的使用条款应更显眼。

### 3.10 国际化与本地化委员会（3 人）

- 中英双语 README 已有；但 skills、错误消息、报告模板英文覆盖不全。
- 战略判断：**先深耕中文市场（硕博论文 + 中文期刊 GB/T 7714），再以"确定性审计"差异化故事出海**。中文市场竞争烈度低于英文（Paperpal/Writefull 未深耕 GB/T 场景），且 audit_project/学位论文是独家钩子。

## 四、战略共识：一句话方向

> **"把 ScholarSeed 打造成学术论文世界的 Ruff/ESLint：确定性的检查器 + 可进 CI 的门禁 + 可复现的证据链，从'一个插件'升级为'论文流水线的基础设施'。"**

三步走：
1. **立信**（3 个月）：补齐 AI 阳性基准、拆包上 PyPI、隐私披露——让产品"可信、可达、可用"。
2. **借力**（6 个月）：GitHub Action 门禁模板 + MCP Registry + 高校社群内容——借 agent 生态与 CI 文化指数级铺开。
3. **变现**（12 个月）：Team/Institution 层试点——在已验证的增长曲线上加商业模式。

详细任务分解与验收标准见 [ROADMAP.md](ROADMAP.md)。
